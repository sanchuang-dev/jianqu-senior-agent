# JQ-004｜Launcher HOME 主屏设计执行稿（第一轮）

> 对应 Issue [JQ-004 #7](https://github.com/sanchuang-dev/jianqu-senior-agent/issues/7)
> 产品依据：[PRD V0.2 Draft PR #6](https://github.com/sanchuang-dev/jianqu-senior-agent/pull/6)；V0.2 未合并，01–08 仍是候选顺序
> 状态：**HOME 代码已实现并通过本地 Android 构建／Lint；尚未进行模拟器及实机 UI 验收**
> 实施基线：`dev`，仅针对 HOME 及保留全部应用能力；不触及生产、发布或真实外部服务

## 1. 核对过的当前代码事实

- `app/src/main/java/cn/sanchuang/jianqu/LauncherActivity.kt` 目前把**全部真实已安装应用**直接显示在 HOME 长滚动区，顶部还有“我的闺蜜机”标题和设备服务占位；这不符合 V0.2 对 HOME 的定位。
- 当前 `LauncherApps.getActivityList`、图标获取和 `startMainActivity` 已存在；保留真实系统目录能力，不因主屏改版而丢失。
- `AndroidManifest.xml` 已注册 HOME 与 LAUNCHER intent filter；当前是普通安装 APK，不能预设系统锁机、隐藏系统导航或厂商权限。
- JQ-003 订阅与小暖仍在 [Draft PR #5](https://github.com/sanchuang-dev/jianqu-senior-agent/pull/5)，不把其未合并代码当成 dev 现状。
- 目标硬件暂只依据供应商参考：可旋转大型竖屏 Android 设备；没有明确实机分辨率或触控距离。不能用先前生成的机身渲染当测量依据。

## 2. HOME 固定内容顺序

1. **低干扰品牌／设备环境**：三创标识，系统时间日期，网络/必要状态。
2. **当地天气摘要**：城市＋天气图标＋当前温度；点击进入 JQ-006 七日预报。真实数据源没接时显示“天气待接入”，不填虚构数字。
3. **小暖**：单独显著的陪伴入口，强调“点击进入”；JQ-007 前的演示状态只能标注 Mock/未接入。避免把一张聊天服务卡独占整个桌面。
4. **十个固定功能**：固定位置由产品定义。01 家人通话；02 家庭相册；03 影视节目；04 精选商城；05 音乐戏曲；06 健康讲座；07 建政栏目；08 我的服务；**09 设置**；**10 全部应用**。前八个名字仍待产品最后确认。
5. **SOS**：十宫格之外的专用明显入口，位置不被促销遮挡、不依赖小暖或设备订阅；未接真实救助链路时点击进入明确“不具备真实求助能力”的说明，不显示发出/送达成功。

**结构示意（功能顺序，不代表比例尺寸）：**

```text
┌───────────────────────────────────┐
│ 三创           时间、日期          │
│                [当地天气] → 7天    │
├───────────────────────────────────┤
│ [小暖]   点击进入交互              │
├───────────────────────────────────┤
│ [01 家人通话]  [02 家庭相册]        │
│ [03 影视节目]  [04 精选商城]        │
│ [05 音乐戏曲]  [06 健康讲座]        │
│ [07 建政栏目]  [08 我的服务]        │
│ [09 设置]      [10 全部应用]        │
├───────────────────────────────────┤
│        [ SOS 紧急求助 ]            │
└───────────────────────────────────┘
```

初步默认竖屏可采用 **2 列 × 5 行**，横屏可改为 **5 列 × 2 行**；只是响应式起始假设，实际需按屏幕物理尺寸、可触摸范围、时间/小暖区域一起验收。不能为了塞进一屏把字号缩得不可读。

## 3. 每个入口的交互真相

| 入口 | JQ-004 本卡允许的结果 | 后续真正消费者 |
| --- | --- | --- |
| 时间／日期 | 真实系统时间可见；此阶段不新建日历功能 | HOME |
| 天气 | 明确“未接入/示例”的摘要与可靠点击接缝 | JQ-006 |
| 小暖 | 入口可见；没有合入的 Mock 不得被标成可用 | JQ-007，依赖 JQ-003 |
| 01、02、03、04、05、06、07 | 固定可点击入口，尚未接入应诚实提示，不以假数据伪装正式可用 | JQ-008、009、010 |
| 08 我的服务 | 保留当前可用设备服务占位；不在 HOME 重做套餐业务 | JQ-007 |
| 09 设置 | 固定可达的轻量页/受支持系统设置入口 | JQ-005 |
| **10 全部应用** | **本卡必须已有可用的原始真实 App 目录，并可真正启动系统应用** | JQ-005 后续加搜索与 UI 整理 |
| SOS | 显著独立入口；没有真实接收机制前不显示救援成功 | JQ-011 |

**硬约束**：JQ-004 不得在已有全部应用目录未迁移可达的情况下移除 HOME 上的真实应用启动能力。这是分阶段合并可用性的关键。

## 4. 视觉基线（先落结构，样张待评审）

- 参考已有 `sanchuang-dev/ai-mirror/design.md` 中的“日光客厅”暖色气质与小暖光晕，不另造未授权的第三套品牌主题。
- 真实三创标识保持识别但不压过时间、天气和可点击功能；**不使用大面积白卡片套卡片**。
- 十个图标每个有**统一触控区域、清晰短标签、稳定位置**；视觉上就是一台 Android 设备桌面，而不是后台表格或商店首页。
- SOS 保持必要警示对比度，但不做只靠颜色识别的按钮，需图形与文字同时表达；误触防护和真实响应由 JQ-011 详细设计。
- 小暖是视觉次重心，位于环境信息和功能区之间，不用真人角色立绘冒充实时 AI。
- 页面不要出现“已安装应用 156 个”这种 HOME 主信息；具体数量仅在“全部应用”中呈现。
- 空态／不可用态用易懂的人话；不显示程序性的“开发中错误码”。

## 5. 首轮交付与验收门槛

**第一段：设计评审。** 根据此文件产出**可核查的竖屏布局稿**和至少一种横屏布局应对，确认十宫格、小暖、天气、SOS 的实际空间比例。产品负责人接受视觉方向前不扩散修改内容/商城/通话页面。

**第二段：最小 HOME 实现。** 从 `dev` 开始，对 `LauncherActivity` 的 HOME 和旧应用目录进行最小必要拆分；“全部应用”立刻能访问真实系统目录。未实现外部业务只提供诚实接缝。

**第三段：验证与维护者评审。** Android 构建；可运行环境点击 HOME → 全部应用 → 真实应用启动 → Home 返回；竖/横屏 UI 证据；关闭网络基础 HOME 仍可用。真实设备无条件时明确记录未测，不能用 CI 代替 OEM 验收。

**禁止越界：** 不接真实天气 API、微信/腾讯云视频通信、支付、真实救助、LLM 或账户；不合并 JQ-003；不自发修改 V0.2 PRD 候选决策。
