> 产品：见趣·闺蜜机（名称暂用，非商标确认）  
> 本文是本仓库 Android 原型的产品真相源；五端总体业务仍由 [ai-mirror 产品基线](https://github.com/sanchuang-dev/ai-mirror/blob/main/docs/product/elder-companion-v0.1.md) 负责。

## 0. 判读规则

- **[已确认]**：本轮用户明确提出的要求。
- **[原型建议]**：为形成可操作演示所做的最小设计假设，可由产品负责人调整。
- **[待验证]**：设备实测、真实 AI 模型、实现接口或商业规则尚无证据。
- **[模拟]**：可点击/可交互的原型效果，不等于真实支付、真实订阅、真实 Agent 执行。

## 1. 产品定义

**[已确认] 一句话**：在普通 Android 闺蜜机上安装带品牌标识的第三方 Launcher，展示系统已安装的可启动应用，并通过**订阅这台设备**获得服务；在「我的闺蜜机」中查看已开通的套餐与服务，体验有不同性格的**小暖（AI 生活伙伴）**。

- 首个落地场景：养老院，面向老人日常使用；不因此开发养老院的内部管理系统。
- 首批硬件开发底线：**Android 11+ / 4GB RAM**。用户于 2026-11-19 提供的供应商参考配置见下节；**不将参考表等同于实机已经验收**。
- 安装方式：**普通 APK**，用户可设置为默认桌面；不依赖 Root、系统签名、出厂预装、设备所有者权限。
- 定位：**产品原型**，不是量产系统、实际支付产品、已验证的养老照护服务或系统级防绕过设备锁。
- 不与现有 `ai-mirror` Web 展厅争夺统一业务首页；该原型关注 Android 桌面、设备订阅与私人 Agent 的最小真实交互。

## 2. 一期目标与非目标

### 一期目标（P0）
1. 让闺蜜机安装 APK 后显示我们的品牌信息，能作为用户选定的默认 Launcher。
2. 不设白名单，发现并展示 Android 系统对 Launcher 暴露的**全部可启动已安装应用**，点击能启动。
3. 演示「**用户自主选择套餐 → 开通当前设备订阅 → 设备获得服务**」的流程。
4. 提供「**我的闺蜜机**」，展示该设备已有的订阅套餐、服务和可用状态。
5. 体验**老人版本私人 Agent**：可选择陪伴角色、发起对话，并展示至少一种简单的设备办事能力（见 §4）。
6. 核心保持轻量、可扩展，Agent/订阅演示失败不能导致 Launcher 无法使用。

### 非目标（V0.1 不做）
- 真实支付/扣款/退款、续费结算、商家后台、养老院管理系统。
- 真实批量授权后台或机构账户体系、复杂个人/家庭会员规则。
- 不可退出的系统级 Kiosk、系统锁机、远程控制设备、隐藏所有系统应用。
- 自动医疗诊断、替代人工照护、紧急联动、自动购买/支付。
- 生产级长期记忆、用户跨设备同步、全量应用 UI 自动操作、数字人实时渲染。
- 将 `ai-mirror` 已有商城、短剧、活动及其它五端业务全部搬进 Launcher。

## 3. 已确认需求清单

**命名决定（2026-11-19）**：原型 AI 伙伴叫「小暖」；「见趣」仍是闺蜜机产品暂定名，不能混为最终企业品牌。

| ID | 功能 | 确认范围 |
| --- | --- | --- |
| **L-01** | 品牌信息 | 启动后展示我们的 Logo / 品牌信息；素材未定时用显式占位，不擅自画正式商标。 |
| **L-02** | 应用目录 | 设备中系统允许普通 Launcher 枚举的**所有可启动已安装应用**，不按业务筛选；图标、名称、点击启动，安装/卸载后更新。 |
| **L-03** | 设备订阅（演示） | A 模式：**订阅归设备**，而非个人/家庭；用户自主选择并模拟开通后，设备获得服务使用资格。 |
| **L-03a** | 批量订阅兼容 | 养老院可能同时开通多台设备；原型可用模拟设备集合说明批量授权，不要求建设真实批量后台。 |
| **L-04** | 我的闺蜜机 | 显示当前设备的订阅状态，以及老人已订阅的各类闺蜜机套餐/服务；不预设真实价格、支付方或账期。 |
| **A-01** | 小暖 · AI 生活伙伴 | **[已确认]** 原有见趣视觉原型的伙伴名称「小暖」沿用为本原型 Agent 名称；V0.1 仅演示对话与简单办事，不接真实模型。 |
| **A-02** | 角色体验 | 「严厉的慈父」「高冷的御姐」「傻甜的小妹」是小暖原型的**候选角色/风格玩法**，不是三个独立 Agent 品牌，也不是已定稿的商品。 |

**L-03 与 L-04 的区别**：L-03 回答「这台设备有没有订阅并能获得服务」，L-04 回答「这台设备开通了哪些套餐和服务」。付费主体、账号与服务计价暂不定义。

## 4. 原型最小交互

### F-01｜打开设备 → 使用应用
1. 用户打开 Launcher，看到品牌区和应用目录。
2. 自动读取可启动已安装应用，展示真实名称和图标；没有可用应用时有空态。
3. 点击应用进入真实 Android App；按 Home 键可回到选定的 Launcher。
4. 新安装/卸载应用后，重新进入或收到系统回调时刷新应用列表。
5. **[边界]** 只能保证系统向普通 Launcher 开放的可启动入口，不能展示/启动所有后台包或受限制的系统组件。

### F-02｜自主订阅当前设备 → 我的闺蜜机
1. 设备显示「尚未开通服务」的**演示状态**和「开通服务」入口。
2. 用户浏览示例套餐、选择并**确认模拟开通**；界面明确「原型演示，不会扣费」。
3. 设备订阅状态由演示前的未开通变成「服务可用」。
4. 进入「我的闺蜜机」，看到当前设备与可用的套餐/服务卡片。
5. 批量场景通过多个模拟设备记录体现「一次开通多个设备」概念，不要求为老人增加复杂管理界面。
6. **[边界]** 普通 Launcher 能约束自己的页面与服务入口，但无法封锁 Android 系统或阻止用户切换默认桌面；不得假装为系统级防绕过授权。

### F-03｜选择 AI 角色 → 陪伴 → 简单办事
1. 在「我的闺蜜机」进入一个已开通的 AI 服务，选择一种候选角色。
2. 原型以本地预设对话展示小暖在不同角色下的语气和交互风格，明确标识模拟；老人主动发起文本交互（语音非本期必要条件）。
3. **[原型建议]** 演示一个「帮我打开相册/某个已安装应用」的动作：Agent 提议 → 指向真实可启动应用 → 由 Launcher 使用受限的 Android Intent/Launcher API 执行；找不到应用时明确说明。
4. AI 角色风格变化不改变事实、安全与隐私约束；不冒充真实亲属、护理人员或医疗专业人员。
5. **演示真实性**：本期不接真实模型，固定台词显著标记为「模拟 AI」；设备应用启动若真实执行，必须与模拟对话明确区分。

## 5. 原型界面清单（不是最终视觉设计）

| 代号 | 页面/区域 | 最小内容 |
| --- | --- | --- |
| S-01 | 启动/品牌桌面 | Logo、品牌信息、应用目录、我的闺蜜机入口 |
| S-02 | 设备订阅演示 | 当前设备状态、示例套餐、模拟开通与反馈 |
| S-03 | 我的闺蜜机 | 已开通套餐/服务、服务可用状态、Agent 入口 |
| S-04 | Agent 角色选择 | 候选角色和简短风格说明 |
| S-05 | Agent 对话 | 清晰可读的对话界面、返回/退出、演示/真实状态标识 |
| S-06 | 批量订阅说明（可选演示） | 模拟多台设备受同一开通操作影响；不做后台 |

**[原型建议]** 适老交互应采用较大触控区域、清楚的返回路径、可读字体和明确反馈；精确字号、配色与组件须通过真实样机试用确定。

## 6. 数据与安全边界

- **设备权益**：最小演示模型为 `device_demo_id → subscription_state → enabled_services[]`，模拟 ID 不宣称是可信硬件身份。
- **个人隐私**：设备的订阅资格不等于任何一个老人的私人身份；AI 对话、偏好、未来记忆如需落盘，必须另设计使用者隔离与清除策略。
- **养老院共享设备**：换人不能读取上一位老人的对话。V0.1 可优先采用无持久私人记忆的临时会话，不虚构身份认证。
- **敏感建议**：角色不进行诊断或替老人作出医疗/财务决定，不利用老人的孤独感制造依赖或诱导订阅。
- **操作权限**：Agent 能调用的设备工具必须明确列出，不能因为叫“Agent”就默认获得无障碍全局操控或系统权限。
- **订阅安全**：模拟状态仅用于演示，不能当作真实授权与防盗版证明。

## 7. 技术建议（待 PoC 验证，不是本期必须施工）

- **Android**：Kotlin；基础桌面优先使用成熟原生 Views 或轻量 UI 方案，Compose 是否使用按真实 4GB 低端样机测量后决定。
- **Launcher**：HOME Intent / 默认桌面选择；`LauncherApps` 发现可启动应用，监听变化；实际 ROM 兼容行为需测试。
- **扩展**：核心只管品牌、桌面、应用发现与启动；Agent、订阅界面与未来套餐服务作为独立边界；优先通过 Intent/Deep Link 连接独立 App，而非下载任意动态代码。
- **AI**：**V0.1 不接模型、不做云端 AI 服务**；使用本地预设脚本与受控设备动作展示玩法，未来如升级为真实 Agent 再另行选型。
- **可靠性**：没有网络或 AI 服务异常时，基础 Launcher 与本机已安装应用仍能正常访问；不可因订阅/Agent 网络失败使设备无法回到桌面。
- **性能**：启动速度、RAM、应用列表首屏速度、触控帧率与长时间运行稳定性均以真实硬件测试为准；当前不虚报具体指标。

## 8. 原型验收标准与证据

- [ ] 在至少一台符合 **Android 11+ / 4GB RAM** 的真实闺蜜机或明确标记的同级设备上安装普通 APK，可手动选为默认 Launcher。
- [ ] 启动见到品牌区；设备可启动已安装 App 被真实读取、展示和打开，安装/卸载后列表能更新。
- [ ] 「未订阅 → 用户选择套餐 → 模拟开通 → 我的闺蜜机显示已开通服务」全链路可操作，模拟支付与模拟状态可识别。
- [ ] 能用模拟多设备数据演示**按设备授权及批量开通**的概念，不把机构/个人订阅混为一谈。
- [ ] 小暖角色选择与预设对话可操作，明确标注「模拟 AI」；至少一个本机应用启动动作可被验证，真实动作与 Mock 台词分开记录。
- [ ] 主机断网/Agent 请求失败/未安装目标应用时，基础桌面仍可用，错误信息明确。
- [ ] 共享使用场景不会暴露上一轮原型对话内容；无承诺外的健康、支付、系统锁机行为。
- [ ] 验收材料说明：APK 版本、设备型号/Android 版本、可见功能、实际测试结果、截图/录屏、未通过事项。**当前没有任何上述实机测试已通过的证据。**
