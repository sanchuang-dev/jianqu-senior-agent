## 1. 产品定义

**[已确认] 一句话**：在普通 Android 闺蜜机上安装带品牌标识的第三方 Launcher，展示系统已安装的可启动应用，并通过**订阅这台设备**获得服务；在「我的闺蜜机」中查看已开通的套餐与服务，体验有不同性格的**小暖（AI 生活伙伴）**。

- 首个落地场景：养老院，面向老人日常使用；不因此开发养老院的内部管理系统。
- 首批硬件开发底线：**Android 11+ / 4GB RAM**。用户于 2026-11-19 提供的供应商参考配置见下节；**不将参考表等同于实机已经验收**。
- 安装方式：**普通 APK**，用户可设置为默认桌面；不依赖 Root、系统签名、出厂预装、设备所有者权限。
- 定位：**产品原型**，不是量产系统、实际支付产品、已验证的养老照护服务或系统级防绕过设备锁。
- 不与现有 `ai-mirror` Web 展厅争夺统一业务首页；该原型关注 Android 桌面、设备订阅与「小暖」的最小可点击演示。
- **三层命名**：三创（SANCHUANG）是企业品牌；「见趣」只是暂定产品名；「小暖」是已确认的 AI 伙伴名称。品牌文案与 Logo 均不得写死在 Launcher 核心。

## 2. 一期目标与非目标

### 2.0 本轮最终范围（2026-11-19）

**[已确认] 这就是一个模拟玩具**：一个 Kotlin Android 工程、一个普通安装 APK、几个能点的界面。**不接后端、不接真实模型、不支付、不做用户账号或云端记忆**。订阅、套餐、角色台词使用本地模拟；Android 应用目录和实际启动 App 是真实本机能力。提供一键重置演示状态。不要因“Agent/订阅”额外引入复杂工程或管理后台。



### 一期目标（P0）
1. 让闺蜜机安装 APK 后显示我们的品牌信息，能作为用户选定的默认 Launcher。
2. 不设白名单，发现并展示 Android 系统对 Launcher 暴露的**全部可启动已安装应用**，点击能启动。
3. 演示「**用户自主选择套餐 → 开通当前设备订阅 → 设备获得服务**」的流程。
4. 提供「**我的闺蜜机**」，展示该设备已有的订阅套餐、服务和可用状态。
5. 体验**小暖**：一位伙伴、三个候选说话风格，本地预设对话，并通过确认按钮真正打开一个已安装应用（见 §4）。
6. 核心保持轻量、可扩展，Agent/订阅演示失败不能导致 Launcher 无法使用。

### 非目标（V0.1 不做）
- 真实支付/扣款/退款、续费结算、商家后台、养老院管理系统。
- 真实批量授权后台或机构账户体系、复杂个人/家庭会员规则。
- 不可退出的系统级 Kiosk、系统锁机、远程控制设备、隐藏所有系统应用。
- 自动医疗诊断、替代人工照护、紧急联动、自动购买/支付。
- 生产级长期记忆、用户跨设备同步、全量应用 UI 自动操作、数字人实时渲染。
- 将 `ai-mirror` 已有商城、短剧、活动及其它五端业务全部搬进 Launcher。
- 真实模型、云端 AI、TTS/ASR、语音唤醒、摄像头/肤质检测、数字人 SDK、多账号切换、复杂插件系统。

## 4. 原型最小交互

### F-01｜打开设备 → 使用应用
1. 用户打开 Launcher，看到品牌区和应用目录。
2. 自动读取可启动已安装应用，展示真实名称和图标；没有可用应用时有空态。
3. 点击应用进入真实 Android App；按 Home 键可回到选定的 Launcher。
4. 新安装/卸载应用后，重新进入或收到系统回调时刷新应用列表。
5. **[边界]** 只能保证系统向普通 Launcher 开放的可启动入口，不能展示/启动所有后台包或受限制的系统组件。

### F-02｜自主订阅当前设备 → 我的闺蜜机
1. 设备显示「尚未开通服务」的**演示状态**和「开通服务」入口。
2. 用户浏览**虚构示例套餐**、选择并**确认模拟开通**；界面明确「原型演示，不会扣费」，没有订单、价格结算和后台。
3. 本地状态由未开通变成「服务可用」；可以重置并重复演示，不识别真实硬件身份，不需要联网激活。
4. 进入「我的闺蜜机」，看到当前设备与可用的套餐/服务卡片。
5. 批量场景通过多个模拟设备记录体现「一次开通多个设备」概念，不要求为老人增加复杂管理界面。
6. **[边界]** 普通 Launcher 能约束自己的页面与服务入口，但无法封锁 Android 系统或阻止用户切换默认桌面；不得假装为系统级防绕过授权。

### F-03｜选择 AI 角色 → 陪伴 → 简单办事
1. 在「我的闺蜜机」进入「小暖」，选择一种候选说话风格；名称始终是同一个伙伴。
2. 原型以本地预设对话展示小暖在不同角色下的语气和交互风格，明确标识模拟；老人主动发起文本交互（语音非本期必要条件）。
3. **[原型建议]** 用预设按钮或固定触发语句演示「帮我打开相册/某个已安装应用」：模拟小暖回应 → 用户点击确认 → Launcher 启动真实已安装应用；找不到则提示。**不要求真正的自然语言理解或跨 App 自动操作。**
4. AI 角色风格变化不改变事实、安全与隐私约束；不冒充真实亲属、护理人员或医疗专业人员。
5. **演示真实性**：本期不接真实模型，固定台词显著标记为「模拟 AI」；设备应用启动若真实执行，必须与模拟对话明确区分。

## 6. 数据与安全边界

- **设备权益**：最小演示模型为 `device_demo_id → subscription_state → enabled_services[]`，模拟 ID 不宣称是可信硬件身份。
- **个人隐私**：设备的订阅资格不等于任何一个老人的私人身份；AI 对话、偏好、未来记忆如需落盘，必须另设计使用者隔离与清除策略。
- **养老院共享设备**：换人不能读取上一位老人的对话。V0.1 可优先采用无持久私人记忆的临时会话，不虚构身份认证。
- **敏感建议**：角色不进行诊断或替老人作出医疗/财务决定，不利用老人的孤独感制造依赖或诱导订阅。
- **操作权限**：Agent 能调用的设备工具必须明确列出，不能因为叫“Agent”就默认获得无障碍全局操控或系统权限。
- **订阅安全**：模拟状态仅用于演示，不能当作真实授权与防盗版证明。

## 7. 极简技术定案（2026-11-19）

- **形态**：一个 Kotlin 原生 Android 工程、一个普通安装 APK，基线 Android 11+、4GB RAM；**竖屏优先**，对可旋转屏幕保留调整空间。
- **Launcher**：官方 HOME/默认桌面机制与 `LauncherApps`（必要时用 `PackageManager`）读取当前用户可启动已安装应用和图标，点击启动，安装/卸载后刷新；不承诺显示没有启动入口的所有后台程序。
- **UI**：原生轻量实现，保持页面可读、可触控、可返回；原生 Views 或 Compose 由施工者按工程实际选定，不为一个玩具专门做 UI 框架竞赛。
- **模拟状态**：使用本地内存/偏好存储保存设备演示 ID、订阅状态、示例套餐、当前小暖角色；提供重置演示入口。无数据库服务、云账户、外部授权。
- **小暖**：固定对话脚本与有限按钮分支；一个受控、真实的“打开本机已安装 App”操作。**无真实 AI 模型、无语音识别合成、无联网后台**。
- **代码结构**：只需按桌面/订阅/小暖划分简单职责；不引入独立 APK、插件市场、AIDL、多进程、复杂网络协议或提前抽象的服务平台。
- **失败处理**：断网不影响 Launcher 和本地 Mock；没找到目标应用时明确提示；不能模拟成系统级设备锁。
- **验收**：先确保可以构建并在模拟器操作；ROM 默认桌面切换、真实屏幕适配、系统应用发现与启动最终在实机验证，未执行测试不得宣称通过。

## 8. 原型验收标准与证据

- [ ] 在至少一台符合 **Android 11+ / 4GB RAM** 的真实闺蜜机或明确标记的同级设备上安装普通 APK，可手动选为默认 Launcher。
- [ ] 启动见到品牌区；设备可启动已安装 App 被真实读取、展示和打开，安装/卸载后列表能更新。
- [ ] 「未订阅 → 用户选择套餐 → 模拟开通 → 我的闺蜜机显示已开通服务」全链路可操作，模拟支付与模拟状态可识别。
- [ ] 能用模拟多设备数据演示**按设备授权及批量开通**的概念，不把机构/个人订阅混为一谈。
- [ ] 「小暖」一名、三种候选风格的本地预设对话可操作，清楚标记「模拟 AI」；至少一次真正启动本机已安装 App，界面操作与台词真假清楚区分。
- [ ] 断网仍能使用桌面、应用目录与本地模拟；找不到目标应用有明确提示；模拟订阅可以重置。
- [ ] 共享使用场景不会暴露上一轮原型对话内容；无承诺外的健康、支付、系统锁机行为。
- [ ] 验收材料说明：APK 版本、设备型号/Android 版本、可见功能、实际测试结果、截图/录屏、未通过事项。**当前没有任何上述实机测试已通过的证据。**
