## 1. 产品定位与二期目标

### 1.1 一句话

**[已确认] 闺蜜机 Launcher 是一台大屏 Android 设备的 HOME 主桌面，而不是一个 App 列表页，也不是小暖聊天页或后台控制台。**

主屏应让用户自然感知“回到设备桌面”，在一个稳定界面中完成：查看时间/天气、进入小暖、点击十个预设功能、必要时求助，以及访问系统全部可启动应用。

### 1.2 本期设计目标

1. **桌面感**：时间、日期、天气是设备环境信息；十个功能快捷入口是日常操作区域；小暖是显著但不垄断的服务入口。
2. **固定、少心智负担**：十个位置数量、结构及次序由产品定义；**不做自由拖拽、自动排序、桌面整理模式、用户自选 10–12 宫格**。
3. **混合入口**：十个功能可以指向 Android 已安装 App、Launcher 内建轻量功能或三创现有服务。用户只看到一致的功能界面，不用理解技术区别。
4. **能回家**：进入任何服务后，Android Home 应回到真正的 Launcher 首页；服务故障不影响 HOME／全部应用。
5. **真实与原型分明**：应用发现和启动是真实本机能力；未接通的通话、SOS、天气、内容、订阅必须明确演示／不可用边界。
6. **先完成产品流程，再做视觉**：避免堆卡片、手机界面直接放大或制造虚假的“系统级权限”。

### 1.3 范围

**[已确认]** 本次是第二期**产品与 UI 原型**定义，不承诺同阶段完成真实微信通话、可靠救助平台、支付、全部内容供给、真实 LLM、联网设备授权或养老院后台。

**[继承]** 普通第三方 APK，Android HOME 机制；不依赖 Root、系统签名、Device Owner、厂家预装或锁机能力。既有 V0.1 本地订阅／小暖 Mock 可在原型中复用。

## 2. 目标设备、使用方式与隐私

- **[继承]** 参考供应商 21.5–32 英寸可旋转大屏、Android 11+、4GB+64GB 起；实际机型、像素、屏幕密度、摄像头/麦克风、ROM 的 HOME/旋转行为**待实机核验**。上一轮渲染的落地机外观不是已确认的真机外形。
- **[继承上层产品]** 个人长期使用优先，也存在养老院公共服务／演示场景；**机构采购不必然等于多人共用**。
- **[待决策]** Launcher V0.2 是否提供显式“个人专用／公共共享”使用状态及入口，及切换方式。不要由采购人类型自动判定。
- 设备级订阅资格 ≠ 老人身份。亲属联系人、相册、聊天、订单和私人偏好不应因“这台设备已订阅”就对下一位使用者开放。
- 公共使用场景不得默认自动显示／拨打上一位使用者的联系人，不保留上一位用户的聊天和私密内容。
- 家属/机构付款不自动获得读取私密聊天或个人相册的权限。

## 3. 主屏信息架构（V0.2 核心）

### 3.1 固定布局原则

- **[已确认] 平衡型桌面 B**：小暖是醒目的一块，而不是独占首屏；天气与时间、十个固定功能同样重要。
- **[已确认] 固定十个入口**：位置 01–10 由我们在产品中定义，不提供桌面自由编辑功能；不按使用频率重排。
- **[已确认] 09「设置」、10「全部应用」固定**，不挪走、不用隐藏手势代替。
- **[已确认] 天气和小暖有首页独立点击入口**，不占十个位置。
- **[已确认] SOS 求助为十宫格之外的独立入口**，与订阅无关；其**真实触发与送达能力仍待验证**，未接入前不能显示假“报警成功”。
- 主屏优先一个屏幕内完成常用操作；根据真实分辨率和系统栏重排，不以纵向长滚动页面堆满模块。
- 入口视觉不做十张白卡片套卡片；使用清楚的功能图标、中文短名称、稳定的触控位置。HOME 顶部不展示「三创 / SANCHUANG」品牌 Logo 或文字，避免占据环境信息空间。

### 3.2 主屏内容区域

| 区域 | 内容与点击行为 | 状态 |
| --- | --- | --- |
| 顶部信息 | 系统时间与日期；不设三创品牌栏 | [已确认] |
| 当地天气 | 放在 HOME 左侧日期正下方，**城市 · 温度 · 天气现象单行显示**（缺数据则显示诚实的状态文案）；点击进入未来 7 天天气。横屏右侧显示已批准的「小暖」透明人物插画，作为 APK 内置资源，不覆盖天气与入口；竖屏隐藏插画；不得放回独立天气卡或使用远程背景图 | [已确认] 布局与行为；真实数据以独立天气服务验证为准 |

### 3.3 天气的最小状态契约

- 首页显示所选城市的当前天气与温度；点击查看未来 7 天预报，包含每日日期、天气状况与最高／最低温（依可用数据源）。
- **[建议]** 城市可手动设置；经用户授权后才尝试设备定位。设备位置≠操作人员手机所在地。
- 数据源、刷新频率、缓存与来源标注 [待验证]；**V0.2 原型若未接真实 API，应清楚显示“示例天气”，绝不伪称当地实时值**。
- 加载、拒绝定位、缺城市、离线缓存过期、API 失败均需明确 UI。联网天气失败不阻断 HOME 或离线启动 App。

## 5. 关键用户流程与必备状态

### F-01｜开机／Home → 桌面 → 全部应用 → 启动 App

1. 进入 Launcher 主屏：时间天气、小暖、十个功能、SOS 可见；十个位置不自动变化。
2. 点“全部应用”进入独立应用目录；读取当前用户系统可见的**全部有启动入口的已安装应用**，显示原始名称和图标。
3. [建议] 提供搜索与长列表滚动；安装/卸载后刷新。点击真实 App 由 Android 启动。
4. Android Home 回主屏，不落到应用目录、套餐或上一位用户聊天页。
5. 处理目录为空、应用被移除／停用、启动失败、服务入口不可用、横竖屏切换、断网与重入。

### F-02｜当地天气 → 7 天预报

1. 点首页天气摘要进入“未来 7 天天气”。
2. 展示城市、更新时间、当日摘要及逐日预报，提供清晰返回。
3. 城市未设置、定位拒绝、断网／数据过期时正确降级；使用缓存须提示旧数据。
4. [待验证] 真实天气供应商、定位方案、联网权限、调用量与成本。

### F-03｜小暖 → 交互

1. 点击首页独立小暖入口，直接到交互界面，不必先打开“我的服务”再找按钮。
2. 继承 V0.1 同一个“小暖”、候选风格与本地模拟对话；始终区分真实模型和固定脚本。
3. 涉及功能执行需有可核查动作及人工确认；例如打开实际已安装 App。
4. [待决策] 未订阅时能否进入基础体验、角色风格从哪里切换、是否保留入口独立于订阅。
5. 私密陪伴/成人角色体验**仅是后续讨论方向**，不在公开十宫格暴露，不纳入本期实施与验收；涉及共享设备的身份与隐私控制需先成立。

### F-04｜家人通话 → 联系人 → 呼叫 → 接通／失败

1. 点击家人通话，看到**事先绑定且获得授权**的家人；不得自动宣称能读取微信通讯录。
2. 未绑定时提供家属绑定说明或可验证绑定流程；公共共享设备不能呈现上位使用者的联系人。
3. 选择家人 → 确认发起视频呼叫 → 等待接听 → 接通/拒接/无人接听/离线/失败 → 挂断返回。
4. 摄像头和麦克风权限需显式申请与回退；按设备真实硬件能力决定是否支持视频。
5. [待验证] 候选技术路线为智能设备与微信用户之间的授权呼叫服务（如腾讯云 TWeCall）；**不等于拥有直接调用原生微信指定好友视频电话的公开能力**。SDK、微信小程序、设备绑定、资质、费用、实时链路均须单独技术 POC 验证。
6. 本期未做成真实链路时，只能演示流程并标识“通话模拟”，不伪造对方已接听。

### F-05｜SOS → 求助 → 等待响应／失败

1. SOS 是主屏独立、持续可发现的求助控件，不依赖小暖与订阅。
2. [待决策] 默认响应人：机构护理站、家属还是现场联系人；不同部署环境如何配置；误触防护的触发方式。
3. 真实功能必须区分“发出请求”“对方已收到”“有人确认接应”，有无人响应、断网和备用联系方式的降级。
4. 若设备本身具备电话能力，可考虑调用系统拨号器；不能假定 Android 大屏可直接拨打电话。
5. **在真实通知、可靠回执与责任链验收前，SOS 页面必须显著标识为原型，不允许模拟‘已经报警’或‘救助已送达’的成功状态。**
6. 未来实体求助器／设备厂商硬件键为另行评估项，不预设硬件接口已可用。

### F-06｜内容栏目 → 详情 → 播放

影视节目、音乐戏曲、健康讲座、建政栏目共享基本页面系统：列表/分类 → 内容详情 → 播放/阅读 → 返回。

- [待决策] 搜索、收藏、续播、最近播放、直播/录播和内容账户要求。
- 内容来源、授权、更新频率与播放器技术尚需确定；不能把单页设计稿当成真实内容服务。
- 健康讲座区分医学科普与推广内容，不提供诊疗承诺；建政栏目区分时政事实、观点评论与日期来源。
- 共用模板而非四套独立播放器；栏目特殊内容采用可复用组件扩展。

### F-07｜精选商城 → 商品 → 外部业务

点“精选商城”进入现有商城（App/H5/独立服务待定），返回仍能找到 Launcher 主屏；商品、库存、价格、订单和支付由商城真实系统负责。若仅演示，标注示例与不可交易。**支付／扣款不能由小暖或 Launcher 自动完成。**

### F-08｜设备服务 → 套餐与权益

从固定位置 08 进入当前设备服务：未开通 → 选择示例套餐 → 确认模拟开通 → 已开通服务列表 → 重置。承接 V0.1 “订阅这台机”而不是按人/家庭订阅；机构批量场景沿用本地模拟记录，**不建真实批量授权后台**。公共/私人资料不从设备权益推导。

### F-09｜设置／首次使用

- [建议] 简短首次进入说明，尤其是如何选择默认桌面、配置城市和基本网络；不做冗长新手向导。
- 设置范围 [待决策]：城市、时间/日期系统设置跳转、音量、显示/亮度（依据权限）、网络跳转、桌面版本与帮助；不是应用编辑模式。
- 不宣称能修改没有系统权限的设置；设置失效或拒绝权限要有返回路径。

### F-10｜相册及共享使用

本地照片与云端相册来源 [待决策]；未授权/无照片要有空态，不假造家庭照片。若跨人共用设备，本人离开/退出后不应继续展示私人相册、联系人、聊天或订单；是否登录、扫码和超时退出由后续隐私设计决定。

## 7. 视觉与适老交互规范（设计约束，不是已定像素）

1. **大型设备优先**，先按真实物理尺寸、屏幕密度和使用距离选择字号/触控范围；不机械放大手机截图。
2. 竖屏为主，横屏内容重排；3×4、4×3 等网格均只是布局候选，**十个功能数量和顺序固定**。
3. 首页重视留白、明确层级和触控反馈；不要白卡套白卡、整屏长列表或 156 个图标直接出现在 HOME。
4. 真实 Android App 图标显示其系统图标，不伪造“微信”“健康服务”功能已经可用。
5. SOS 需要视觉可发现性，不能被商业促销遮挡；具体固定位置、颜色、确认时长待可用性设计。
6. 小暖可以参考原有光晕设计语言，不要求虚构真人头像、实时视频人像或实际摄像头场景。
7. 使用三创已授权品牌素材；“见趣”为暂用名，不制作/暗示已获批准的专属标识。
8. 视障、听障和行动受限场景至少考虑文字可读、图标+文字双提示、可触目标、声音/视觉反馈与误触恢复。

## 8. 系统、数据与权限边界

- Launcher 必须在 Android 普通应用权限下使用标准 HOME 与应用启动能力；不能依赖不可获得的系统级 API。
- **网络天气、微信通信、商城、内容服务各自独立失败**，不影响桌面离线和本机 App 启动。
- Android 真实应用目录与内部业务入口有不同来源，但用户体验保持一致；内部服务未提供时应明确显示不可用。
- 不读取完整微信好友清单、聊天记录；联系人仅通过具体服务的合规授权绑定。
- 不因服务已订阅而自动启用相机、麦克风、私密聊天或求助消息。
- **支付及紧急求助属于高风险外部操作**，不能使用“按钮点了即成功”的假反馈。
- 不建立养老院护理工作台、床位、排班、结算、直播平台或另一套内容中台。
- 二期若需要新的服务端能力，必须另开明确产品合同与工程验证任务，不能悄悄塞进普通 APK 改造。

## 11. 设计与施工建议：先少量验证，不行政拆卡

这是**建议顺序**，不是已批准的施工计划：

1. 产品评审：固定入口候选、个人/公共使用方式、SOS 和通话的安全边界。
2. UI 结构与视觉样张：HOME 竖/横屏、十宫格、天气、小暖、SOS 的状态规范。
3. 最小可点击链路：HOME → 天气 7 日；HOME → 小暖；HOME → 全部应用；HOME → 家人通话模拟流程。
4. 复用内容页面模板与现有商城／订阅业务，避免四套播放器、第二套商城。
5. 独立进行设备验证和 TWeCall/SOS 外部能力可行性 POC；之后再决定是否纳入实装。
6. 各工程切片以新增 Issue 的验收合同为准；**本 PRD 创建本身不授权其它卡施工、发版、支付或真实求助上线；JQ-004 已获独立实施授权，JQ-003 已并入 dev**。
